# Hybrid 5-device factory timer

Validated fleet mapping:

| Device | MCU target | Profile defaults | Build directory |
|---|---|---|---|
| ESP01 | ESP32 | sdkconfig.defaults.esp01 | build-esp01 |
| ESP02 | ESP32 | sdkconfig.defaults.esp02 | build-esp02 |
| ESP03 | ESP32-S3 | sdkconfig.defaults.esp03 | build-esp03 |
| ESP04 | ESP32-S3 | sdkconfig.defaults.esp04 | build-esp04 |
| ESP05 | ESP32-S3 | sdkconfig.defaults.esp05 | build-esp05 |

The application source is shared by both MCU families. The FCT2 protocol, deadline-task START_AT scheduler, STARTED telemetry, path-delay experiment, Wi-Fi power-save disablement, and bad-IP rejection are unchanged.

## Why ESP03-ESP05 do not ship with copied full sdkconfig files

A generated sdkconfig contains target-specific SOC/Kconfig values. Copying the ESP32-generated sdkconfig to ESP32-S3 is incorrect even though both chips use Xtensa. The S3 profiles are therefore generated by ESP-IDF on the development machine with `set-target esp32s3`.

## Configure all five profiles

Open an ESP-IDF PowerShell terminal in this folder and run:

```powershell
.\configure_hybrid_profiles.ps1
```

This generates target-correct `sdkconfig.esp03`, `sdkconfig.esp04`, and `sdkconfig.esp05` files for ESP32-S3 and separate build directories.

To configure only one profile:

```powershell
.\configure_hybrid_profiles.ps1 -Device ESP03
```

## Build

```powershell
.\build_device.ps1 -Device ESP01
.\build_device.ps1 -Device ESP02
.\build_device.ps1 -Device ESP03
.\build_device.ps1 -Device ESP04
.\build_device.ps1 -Device ESP05
```

Verify target and identity after generation:

```powershell
Select-String .\sdkconfig.esp03 -Pattern 'CONFIG_IDF_TARGET|CONFIG_FACTORY_DEVICE_ID'
```

Expected for ESP03:

```text
CONFIG_IDF_TARGET="esp32s3"
CONFIG_IDF_TARGET_ESP32S3=y
CONFIG_FACTORY_DEVICE_ID="ESP03"
```

ESP01/ESP02 should show target `esp32`; ESP03/ESP04/ESP05 should show `esp32s3`.

## Flash

Example:

```powershell
.\flash_device.ps1 -Device ESP03 -Port COM7
```

Use the actual COM port for each device.

## Espressif-IDE

If using IDE build configurations, point each configuration at its own SDKCONFIG and build directory. Do not reuse one `build` directory while changing targets or SDKCONFIG paths.

- ESP01: `sdkconfig.esp01`, `build-esp01`, target `esp32`
- ESP02: `sdkconfig.esp02`, `build-esp02`, target `esp32`
- ESP03: `sdkconfig.esp03`, `build-esp03`, target `esp32s3`
- ESP04: `sdkconfig.esp04`, `build-esp04`, target `esp32s3`
- ESP05: `sdkconfig.esp05`, `build-esp05`, target `esp32s3`

If the S3 module has a different physical flash size, select the actual flash size in menuconfig after the target-correct profile is generated. The timer application itself does not depend on a large flash partition.
