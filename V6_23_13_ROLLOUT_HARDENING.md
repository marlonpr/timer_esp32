# v6.23.13 — rollout hardening

This revision does not change the 4 kHz CPU0 fleet monitor or the 42-field FCT2 STATUS format. It closes rollout-validation gaps around canary sampling phase, S3 coverage, network identity, and controlled heartbeat variants.

## Canary validation

The task and ISR canaries remain compile-time options and are OFF in every normal fleet profile.

Two one-board task-canary profiles are provided:

- `sdkconfig.esp01.telemetry_canary` — classic ESP32.
- `sdkconfig.esp03.telemetry_canary` — ESP32-S3.

Both place a 600 us CPU0 critical section across COMMIT boundary 10, beginning 150 us before the target. The ISR canary remains OFF so the expected STATUS/CSV result is one monitor event and one late COMMIT.

The sampled monitor lateness is phase dependent on the 250 us grid, so the CSV validator accepts `Cpu0MonitorWorstUs` from 100..600 us. The COMMIT delay remains deterministic and must be 300..600 us, with `Cpu0CommitOverlap=1` and `Cpu0MonitorWorstTask=lat_canary`.

## Fleet safety against a canary image

Normal `sdkconfig.esp01` through `sdkconfig.esp15` all keep both canaries OFF. The fleet summary flags every POST_RUN row whose `Cpu0MonitorWorstTask` is `lat_canary`; any such row makes fleet telemetry health WARN and keeps the zero-event rollout item OPEN.

## DHCP and hostname identity

ESP06..ESP15 remain identity-only clones of ESP01. The application uses `esp_netif_create_default_wifi_sta()` and DHCP. There is no static address assignment; the one `esp_netif_set_ip_info()` path clears a rejected lease to zero before DHCP restart.

The station hostname is now set at runtime from `CONFIG_FACTORY_DEVICE_ID` with `esp_netif_set_hostname()`. Thus ESP06..ESP15 inherit network behavior but not ESP01's hostname.

`tools/generate_fleet_sdkconfigs.py --check-only` verifies both the identity-only invariant and this DHCP/hostname source contract.

## Heartbeat-on comparison

Baseline fleet profiles keep RUNNING heartbeats suppressed to reproduce the historical stall workload. Optional `.heartbeat_on` profiles for ESP01..ESP10 are generated by `tools/generate_heartbeat_on_profiles.py`; each differs from its source profile only by `CONFIG_FACTORY_SUPPRESS_RUNNING_HEARTBEAT`.

Use at least one heartbeat-on scale run before the 15-device step if the intended production mode will send RUNNING heartbeats.
